# 分类生图、质检、返修与交付

## 生成路由

- 白底首图：用实拍抠图或受控产品编辑在纯白 #FFFFFF 画布上干净导出，**禁止走「生成后再补角/补边」**（生成图的圆角/AI 透视边缘会出现非纯白像素，易影响主图合规）；多角度、细节同样优先实拍抠图、修图或受控编辑，尽量少重绘产品本身。
- 场景、人物、情绪和礼赠图：生成或合成环境，使用匹配视角的产品实拍锁定产品区域。
- 尺寸、包装、步骤、对比、数据和 A+ 信息图：先获得干净底图，再用可编辑矢量层完成标注与排版。
- 拆解、剖面、原理、兼容和认证图：只有资料充分时制作；优先图解或 3D/矢量示意，不靠生成模型猜测内部结构。
- 多角度、场景组合和 A+ 模块：分别生成合格单图后再组合，避免一次生成造成产品身份漂移。
- A+ 底图按目标宽高比和叙事单独生成或合成。既有主图可提供产品身份、品牌和事实连续性，但不得通过扩边、纯色补宽和挪动文案冒充新的 A+ 场景。

## 生图迭代

1. 对原始实拍做清晰度和身份可见性预检，建立产品不变量；从实拍中选出最干净的一张作为白底首图的抠图底图。
2. 该走「受控编辑/矢量」而非「生成」的：白底首图用实拍抠图 + 纯白 #FFFFFF 画布；尺寸、数据、信息、对比图用干净底图 + 矢量标注层，最小化生成。抠图必须以质检合格为前提（见「图片质量」项），否则按「修边 → 换更干净实拍 → 受控编辑」降级。
3. 按任务卡生成低成本方向草图，用低分辨率快速档；不同方向必须保留相同产品身份和事实。
4. 批量并发生成底图：把一批任务卡的底图一次性并发发给生图模型。先探测并发上限：同时发 3–4 个最小/最低成本请求，观察是否 429、限流或排队；能并发就用并发（默认 3–4，留余量），撞限流就降到可承受并发或分批，或改异步 + 轮询等待。不要「生成一张停一张」——生成完成后一次性按清单批量核对（主体一致性、沟通目标、卖点表达、视觉差异化、文案留白、类型适配）。
5. 对优选方向用最终分辨率高清生成或局部编辑；只编辑责任区域，不无故重做整图。
6. 底图通过后进入专业图文排版；无字版本仅作为内部返修中间件保留，不加入默认用户交付包。

## 质检层级

质检以**影响实际上架与合规**为准：只抓事实、合规、产品/人物一致性、明显畸形/形变/重影/错字、遮挡、硬尺寸与格式、跨分支重复；**不为像素级偏差吹毛求疵**（如背景色 250/254 vs 255、边缘抗锯齿、细微色差等非关键差异），除非违反官方硬性要求且确实影响上架。

### 1. 事实与来源

- 文案、数据、尺寸、认证、对比、内部结构和配件均有事实引用。
- 竞品图片、未授权 Logo、字体或人物素材未进入交付资产。

### 2. 产品与人物一致性

- 产品形态、结构、颜色、接口、标签和配件数量与实拍一致。
- 场景中的产品比例、接触关系和使用方式合理。
- 人物图重点检查手指、肢体、姿势、目光和与产品的交互。

### 3. 图片质量

- 无多余部件、形变、重影、光晕、纹理融化、错误反射或局部模糊。
- 焦点、光线、材质和透视符合图片类型与沟通目标。
- 白底首图抠图专项：边缘干净（无毛边/锯齿/半透明残留）、无残留背景或阴影、颜色亮度与实拍一致、无缺件或误抠（透明、反光、细杆易错）、背景为纯白 #FFFFFF。

### 4. 文案与排版

- OCR、拼写、单位、数字、品牌名和标点准确。
- 层级、对齐、留白、对比度和安全区合格，未遮挡产品关键细节。
- PC 与移动端裁切、字号和阅读顺序分别通过检查。

### 5. 套图与跨分支差异

- 对照任务卡的差异矩阵检查沟通任务、文案重点、场景、动作、视角、景别、产品占比、构图和版式原型。
- A+ 与最相近主图若只改变画布尺寸、纯色区域、产品位置或文字位置，则判定为重复并返回策划阶段。
- 场景主导的 A+ 中，有效环境应铺满或占据画面主体；无信息目的的大面积纯色补位判定为画布适配失败。
- 当实拍证据支持多个视角时，整套图不得长期只使用一两个产品视角。6 张及以上套图若少于 3 个可验证视角族，或超过半数使用同一视角，需给出明确叙事理由，否则返回镜头规划。
- 同一版式骨架连续出现 3 次，或多张图仅左右互换产品与文案，需证明其属于有意的步骤/系列结构，否则返回版式规划。
- 构图与版式是否同质化（普通）：整套图是否大量「居中 + 同占比 + 同版式 + 同景别」、缺乏前中后景 / 景深 / 视觉动线 / 非对称层次；若类型已多样化但排版千篇一律，判为普通并返回版式规划。
- 桌面与移动版本分别检查场景语义、主体位置、裁切和阅读顺序；不能以机械缩放通过。

### 6. 平台与导出

- 数量、尺寸、格式、色彩模式、透明度和文件名符合当前交付要求。
- 白底首图没有文案或不允许的装饰，背景为纯白 #FFFFFF；受影响分支的当前官方要求已核对。仅因背景色或边缘存在数级像素偏差（如 254 vs 255、抗锯齿），一般不作为否掉理由，除非明显灰白或彩色背。

## 定向返修

| 问题 | 返回阶段 |
|---|---|
| 产品结构、配件、人物交互错误 | Prompt、参考图选择或底图局部编辑 |
| 场景、构图、卖点表达不清 | 图片任务卡与 Prompt |
| 主图与 A+ 信息、场景或版式重复 | 分支叙事、信息缺口与差异矩阵 |
| A+ 场景未适配画布、依赖纯色补宽 | A+ 任务卡、目标画布 Prompt 与底图 |
| 产品视角或版式骨架在套图中过度重复 | 镜头覆盖与版式规划 |
| 文案事实或数据错误 | 事实库与文案任务卡 |
| 错字、字号、遮挡、对齐、尺寸线错误 | 矢量排版层 |
| 文件尺寸、命名或格式错误 | 导出阶段 |

每个资产最多自动修复 2 次，每次修复后重新执行受影响层级及其下游检查；**返修预算优先留给真正影响上架/合规的问题**（事实、产品身份、形变、遮挡、硬尺寸与格式、跨分支重复）。对难搞但低价值的细节（如背景色 254 vs 255、边缘抗锯齿），**不无限修补、也不据此否掉**——记录说明，或换用正确的生成/导出路由重做底图；若该资产实际可上架，则纳入交付。真正需重做且超过 2 次仍失败，才标记 `blocked` 并移出交付清单、保留原因。

## 交付

用户资产包至少包含：

- 最终成品图。
- `contact-sheet` 总览图。
- 精简 manifest：`asset_id`、用途、图片类型、尺寸、版本、文件名和状态。

`contact-sheet` 用于快速审阅，不作为 Amazon 上架图片：

- 只收录通过质检并进入交付包的最终成品图，顺序与 manifest 一致。
- 每张缩略图在图外的独立标签区显示 `asset_id` 和核心卖点中文翻译，字号需在总览尺寸下可读。
- 中文来自任务卡中的核心卖点：英文成品文案翻译其主要卖点；无文案图片则用简短中文说明沟通目标或图片用途。
- 标签不得遮挡或改写缩略图中的成品画面；不得把中文翻译回写到最终上架图。

无字底图、SVG 和其他排版过程文件不进入默认用户交付包。只有用户明确要求可编辑源稿时，才按双方约定的格式额外交付；不得因内部使用 SVG 就默认交付 `.svg` 文件。

内部策划与审计材料单独保存：竞品视觉证据、动态图片类型计划、资产任务卡、完整 Prompt、生成记录、质检和返修报告。不要用内部竞品图片替代用户可交付素材。
